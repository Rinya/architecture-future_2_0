## Приоритизация проблем

**Матрица Эйзенхауэра для проблем «Будущее 2.0»:**

|                         | **Срочно**                      | **Не срочно**                        |
|-------------------------|----------------------------------|--------------------------------------|
| **Важно**               | Миграция SQL 2008, облако, ИБ, целевая архитектура, границы доменов | Витрина данных, отказ от легаси, новая интеграция, DevOps, резерв. копии |
| **Не важно**            | Поддержка легаси, документация, временные интеграции              | Рефакторинг старого, редкоисп. отчёты, неисп. дашборды               |


**I. Важно и срочно:**
- Миграция от SQL Server 2008 для DWH (устаревшее ПО, угроза ИБ)
- Перенос в облако критических сервисов (отказоустойчивость, масштабирование)
- Архитектурное описание целевой ландшафтной схемы (уже поручено бизнесом)
- Проработка требований безопасности и регулятора для облака
- Определение границ доменов и стыков

**II. Важно, но не срочно:**
- Замена PowerBuilder и обновление BI-инструментов
- Проектирование витрины данных как единой для всех доменов платформы
- Разработка модульного интеграционного слоя (вынос бизнес-логики из DWH)
- Стратегия постепенного отказа от легаси
- Внедрение современных DataOps/DevOps-процессов
- Разработка политики геораспределенности и резервного копирования

**III. Не важно, но срочно:**
- Поддержка слабых легаси-систем (минимальная до миграции)
- Актуализация документации по текущей ИТ-инфраструктуре
- Внедрение временных интеграционных костылей для новых сервисов

**IV. Не важно и не срочно:**
- Детальный рефакторинг всего старого кода PowerBuilder
- Разработка универсальных отчётов для редкоиспользуемых сценариев в BI
- Отказ от устаревших BI-дашбордов без востребованности

### Итоговая приоритизация (МоSCoW для первых 2-х месяцев):
*   **MUST HAVE (обязательно):**
    *   Определить доменные границы и архитектурный стиль взаимодействия (Data Mesh).
    *   Начать проекты по управлению доступом и отделению чувствительных данных.
    *   Согласовать целевое облако и технологии (DWH, пайплайны).
*   **SHOULD HAVE (желательно):**
    *   Начать миграцию одного пилотного домена (например, «Персонал») в новую архитектуру.
    *   Спроектировать MVP портала самообслуживания.
*   **COULD HAVE (возможно):**
    *   Провести аудит и стабилизацию текущей интеграционной шины.
*   **WON'T HAVE (не сейчас):**
    *   Полный отказ от всех легаси-систем (например, клиентский интерфейс на PowerBuilder может остаться на время, если он стабильно работает).
